CRM Process Mining

Measures how cases actually move through their stages — how often each stage is entered, how often each step from one stage to the next happens and how long it takes, in calendar hours and in working days (weekends and the holidays in CRM's closure calendar left out) — through your own signed-in CRM session, and saves the TOTALS as one small file crm-process-mining-<time>.json. Every request is a read (GET); nothing in CRM is changed. Everything is reduced in this tab: no case id, customer, product, user or exact time leaves it. If several entities could hold the stage history, it asks you which one.

CRM Process Mining

One-time setup

  1. Show the bookmarks bar (Ctrl+Shift+B).
  2. Drag the CRM Process Mining button above onto the bookmarks bar. (Clicking it here does nothing useful.)

Each run

  1. Sign in to CRM as usual and stay on a CRM page, e.g. https://ahecrm.anadoluhayat.com.tr/main.aspx.
  2. Click CRM Process Mining on the bookmarks bar. It reads the whole stage history page by page, so on a large organisation it can take a long time; the console reports every ten pages; progress is visible under F12 → Console.
  3. When it finishes, the browser downloads crm-process-mining-<time>.json.
  4. In the extractor's appsettings.json, set "Run": { "ProcessMiningFile": "<full path to that file>" } together with ReprocessRunId (or ImportFile) and run it.

The file holds totals only. The report made from it is for Enterprise Architecture and is not delivered to the outsource partner.
